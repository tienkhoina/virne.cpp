## Exact differential and safety result

The exact differential passed **24/24** compatibility cases. Every compatible
case matched sequential enumeration/deletion order, partial side effects,
typed failure point, exact stdout bytes, and the complete before/after
filesystem tree.

One additional case is an intentional safety deviation. Python follows an
algorithm-directory symlink and can recursively delete a run outside the
caller-supplied root. C++ resolves and contains the candidate, reports
`unsafe_path_escape`, and leaves the symlink and outside target unchanged. This
is required behavior, not a failed compatibility case.

The original `delete_temp_files` bug remains compatible: an empty directory is
a no-op, while a non-empty directory fails before deleting an entry. The port
does not silently turn it into a working temp-file remover.

Python `shutil.rmtree()` applied to a regular run entry raises
`NotADirectoryError`. The typed C++ boundary represents the same failure point
as `ManagerErrorCode::remove_failed` with
`ManagerOperation::remove_run_tree`; the regular file remains and later entries
are not processed.

## Implementation and engineering gates

- Fixed config members are direct `std::filesystem::path` fields; error and
  operation categories are enums.
- Dynamic filesystem names are consumed once as native paths; the fixed
  `records` child is formed once per run.
- POSIX builds use the libc `opendir`/`readdir`/`stat`/`rmdir` fast path;
  non-POSIX builds retain the `std::filesystem` fallback.
- The implementation carries no mutable component-global state and introduces
  no Threads or third-party library dependency.
