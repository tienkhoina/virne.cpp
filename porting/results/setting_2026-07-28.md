## Tuning measured

The pre-tuning canonical run had one failed row: JSON scalar parse was
0.964692x Python. The public API and compatibility profile were unchanged. The
leaf-only edit:

- classifies a complete Boost.JSON numeric token through its existing view and
  copies only genuinely chunked tokens;
- combines integer detection and precision classification into one scan while
  preserving the existing precise-fallback thresholds;
- preserves exact arbitrary-integer parsing for integer lexemes delivered by
  `on_double`;
- reserves 16 entries for parsed objects; and
- uses Boost's flat open-addressed table for the dynamic key-to-ID boundary,
  while retaining dense direct-ID access in hot loops.

Parser state remains thread-local. Duplicate-key order, deterministic batch
errors/order, reentrant fallback, arbitrary integers, and exact binary64 output
did not change.
